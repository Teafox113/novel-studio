# Novel Studio schema v3

## 目的

長篇故事中的「實際發生時間」通常不等於「讀者閱讀順序」。schema v3 新增雙軸
時間事件，讓倒敘、插敘、預示與延後揭露能被明確記錄，而不必破壞 Binder 的手稿
排列。

## TimelineEvent

| 欄位 | 用途 |
|---|---|
| `storyTimeLabel` | 作者使用的日期、年代或相對時間文字 |
| `storyOrder` | 事件在故事世界中的先後位置 |
| `narrativeOrder` | 事件對讀者揭露的先後位置 |
| `kind` | 場景事件、角色往事、歷史事件或世界事件 |
| `status` | 規劃中、已確認或待確認 |
| `importance` | 1 至 5 的重要程度 |
| `linkedNodeIds` | 對應的一個或多個手稿場景 |
| `linkedEntityIds` | 涉及的人物、地點、勢力、物品或設定 |

兩個順序使用數字保存，因此可以分別排序與重新排列；畫面會計算兩軸位置差異，
提示可能的倒敘、插敘或延後揭露。

## 相容性

- schema v1／v2 會自動升級至 v3。
- 舊場景會依 Binder 階層與排序建立初始時間事件。
- 初始故事時間標示為「未設定故事時間」，不猜測作者的虛構曆法。
- 原有正文、世界觀、Tag、靈感與關係資料不會改寫。
- `.novel` 匯入會驗證事件所連結的場景及世界觀 ID。
