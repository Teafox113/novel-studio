# Novel Studio schema v2

## 目的

長篇小說隨劇情推進會持續增加人物、地點、物品、事件、別名與交互關係。
schema v2 不再把 POV、地點及專有名詞只保存為文字，而是使用穩定 ID 建立圖狀
關聯，讓改名、別名、搜尋與 AI 校對都能指向同一個故事事實。

## 核心資料

| 資料 | 用途 |
|---|---|
| `StoryEntity` | 人物、地點、勢力、物品、設定與專有名詞 |
| `EntityRelation` | 實體之間的親屬、敵對、隸屬、居住等關係 |
| `SceneEntityLink` | 場景的 POV、地點、參與者、提及與主題 |
| `StoryTag` | 可重用的劇情、主題、工作流程及自訂標籤 |
| `TagLink` | Tag 與場景、實體或靈感的多對多關聯 |
| `InspirationItem` | 尚未決定放入手稿的劇情、場景、對白或設定 |

## 靈感取用規則

1. 靈感可以先只保存標題和一句話。
2. 後續可加入類型、Tag 與相關人物／地點。
3. 選擇「轉成場景」後，正文、Tag 與實體關聯會複製到新場景。
4. 原始靈感保留並標示為「已採用」，方便追查構思來源。
5. 已封存的靈感不顯示在左側，但資料仍保留。

## 相容性

- schema v1 專案會在記憶體中自動升級，不直接破壞原始檔。
- 升級使用名稱與實體類型比對既有人物／地點。
- 無法比對時使用確定性 ID 建立新實體，多次載入不會反覆新增。
- `.novel` 匯入會驗證實體、Tag、場景與靈感的參照完整性。
